# Java Parity Implementation Plan

**Reference:** `github.com/cqels/claude` (Java) @ `ecce069` (2026-05).
**Goal:** Close the algorithmic / language-feature gaps between cqels-rs and cqels-java identified in the audit. Track progress per phase.

## Methodology

Per the project's behavioral guidelines:

- **Goal-Driven:** Each task lists a *verify* check. Move on only when the check passes.
- **Surgical:** Each PR touches one feature; no drive-by refactors of unrelated code.
- **Simplicity:** Port the algorithm, not the framework. Skip Java-isms (reflection, complex builder ceremonies) when a leaner Rust equivalent suffices.
- **Pre-commit MANDATORY** (from project CLAUDE.md):
  1. `~/.cargo/bin/cargo fmt --all`
  2. `~/.cargo/bin/cargo clippy --workspace --all-targets -- -D warnings`
  3. `~/.cargo/bin/cargo test --workspace`
  4. `RUSTDOCFLAGS="-Dwarnings" ~/.cargo/bin/cargo doc --workspace --no-deps`

## Phase 1 — Core correctness gaps

### 1.2 Named windows + implicit stream binding (Java PR #31)

**Status note:** Java has parser + AST for `FROM NAMED WINDOW` but execution is unimplemented — `CqelsQueryCompiler` throws `UnsupportedOperationException`, tracked in Java issue #39 (commit `3afb720`). Porting Java's incomplete parser is busywork until Java itself executes named-window queries. **Deferring Phase 1.2b until upstream completes Phase 3.**

- [x] **1.2a Implicit stream binding** (Java Phase 1, complete and working): bare triple patterns in `WHERE` auto-bind to a single `FROM STREAM` when no `STREAM`/`WINDOW` blocks are present.
  - **Verify:** [cqels-core/src/parser/cqelsql.rs](../cqels-core/src/parser/cqelsql.rs) — `apply_implicit_stream_binding`; 6 new parser parity tests covering single-stream binding, multi-triple binding, explicit-block bypass, multi-stream skip, static-graph skip, named-graph skip.
- [x] **1.2b Named window parsing** (`FROM NAMED WINDOW :name ON STREAM <name> [<spec>]` + `WINDOW :name { ... }`): pest grammar extended with `from_named_window` and `window_pattern_group` rules; new `NamedWindowDefinition` AST type carries `(iri, stream, window_spec)`; new `CqelsPatternGroup::Window { window_iri, patterns }` variant. `CqelsQueryDefinition.named_windows` lists the declarations. The window-form rule is tried ahead of the bare `FROM NAMED <iri>` (static graph) form so prefix overlap doesn't shadow it. 7 tests cover declaration registration, `WINDOW {}` pattern groups, prefix-overlap with static `FROM NAMED`, multiple windows with different specs, TRIPLES specs, and error cases.
- [x] **1.2c Named window compile-time lowering** (`compiler::named_window`): a thin pass at the top of `compile_with_store` rewrites `named_windows` + `Window {}` pattern groups into ordinary `streams` + `Stream {}` groups so the rest of the compiler / planner / engine sees only the existing constructs. Same-stream + same-spec windows collapse idempotently; same-stream + conflicting specs are rejected at compile time (multiple distinct specs over the same source stream would need aliased stream views in the runtime — left for a future expansion); `WINDOW {}` references to undeclared IRIs are rejected. Recurses into `OPTIONAL` / `UNION` groups so nested windows are handled. 8 lowering unit tests + 3 end-to-end compile tests cover the supported and rejected cases. **Named-window queries now execute end-to-end** through the existing operator pipeline.

### 1.3 Declarative CEP via FILTER(SEQ()) (Java PR #36)

- [x] Add `SEQ(...)` built-in recognized inside `FILTER` (grammar + AST).
- [x] Compile `FILTER(SEQ(...))` AST nodes to existing `cqels-engine` NFA pipeline.
- **Verify:** 7 parser parity tests + 9 `CepPatternCompiler` tests covering ordering, quantifiers, negation, alias, and window propagation; end-to-end tests run the compiled `Pattern` through `NfaPatternProcessor` over a stream of `RdfStreamElement`s.
- [x] **Single-event + cross-event FILTER predicates** wired into the compiler via `cqels-core::expression::ExpressionEvaluator`. `classify_filters` walks WHERE-level `Filter` groups, parses each expression, classifies by the set of event variables it references, and attaches single-event filters as `where_cond` on that event's stage or cross-event filters as `where_context` on the latest referenced stage. `bind_event_variables` constructs a `BindingSet` from the matched stream element using the event's triple patterns. 4 new e2e tests (single-event keep/drop + cross-event keep/drop) and 1 unit test for variable collection.

## Phase 3 — Performance + persistence

### 3a Parallel hash-join (Java PR `ParallelHashJoinOperator`)

- [x] `ParallelHashJoinOperator<L, R, K, Out>` in `cqels-core::operator::parallel_hash_join`. Sequential build phase materializes the left side into `HashMap<K, Vec<L>>`; concurrent probe phase via `futures::stream::buffer_unordered`.
- [x] `ParallelWindowedAggregateOperator` in `cqels-core::operator::parallel_aggregate` — hash-partitioned parallel windowed aggregation; partitions per-window batches by group key and processes partitions concurrently. 5 tests.
- **Verify:** 6 hash-join tests + 5 aggregate tests — basic join/aggregation, empty inputs, one-to-many, parallelism invariance over {1, 2, 4, 8}, equivalence vs sequential baseline.
- [x] **SWAG CTrie index** in `cqels-core::operator::swag_ctrie` — `TimeIndex<P>` (time-bucketed range index with bag semantics) + `CTrieIndex<K, P>` (fixed-depth trie nesting one `TimeIndex` per leaf, with wildcard partial-key queries). Ported from Java's `org.cqels.operator.aggregate.swag.join.{TimeIndex, CTrieIndex}`. Single-threaded (`BTreeMap` rather than `ConcurrentSkipListMap`) and typed-keys (`K` generic rather than raw `Object`). 18 tests + 1 doctest.
- [x] **SWAG join primitives — layer 1** in `cqels-core::operator::swag_join`: `KeyIndexedTimeIndex<K, P>` (one `TimeIndex` per equi-join key + `IndexStats`), `JoinRecord<E, P>` wrapper, `KeyExtractor` trait alias with `identity()`/`constant()` helpers, and `VariableOrder` / `VariableOrderMethod` value types. 16 tests + 2 doctests. Builds on PR #32; consumed by 3a-layer-2.
- [x] **SWAG pairwise join — layer 2** in `cqels-core::operator::swag_join_state`: `JoinAggregateSpec` trait (ring-algebra contract: payload extraction, zero, add, negate, multiply, per-side payload zero/add, name) + `IntervalBounds` value type + `WindowJoinState<S, K>` stateful operator. Two indexing modes (cross-product via `TimeIndex`, equi-join via `KeyIndexedTimeIndex`); every `insert_*` / `evict_*` returns the F-IVM delta and folds it into a running aggregate. 9 tests + 1 doctest. Java's `WindowJoinState.recomputeParallel(...)` (Tier-2 batch recompute) is deferred to a later slice — it depends on the full planner.
- [x] **SWAG join planner — layer 3** in `cqels-core::operator::swag_join_graph`: `JoinGraph` (declarative topology — relations + edges with temporal windows + adjacency), DFS-based undirected acyclicity + GYO hypergraph acyclicity, `Hypergraph`/`Hyperedge` types with primal-graph construction, `build_variable_order()` (GYO join-tree DFS for acyclic, greedy min-fill for cyclic), plus `FactorizedViewPlan`/`ViewLayer`. Pure-metadata graph — key/payload extractor closures live with the Layer-4 executor. 19 tests + 1 doctest.
- [x] **SWAG join specs + windowed aggregator — layer 4 (pairwise half)** in `cqels-core::operator::swag_join_specs`: 4 concrete `JoinAggregateSpec` impls (`CountSpec`, `SumLeftSpec`, `SumRightSpec`, `SumProductSpec`) + `F64Bits` newtype for hash-stable f64 payloads + `WindowedJoinAggregator` streaming runner driven by `JoinUpdate<L, R>` events (`InsertLeft` / `InsertRight` / `EvictLeft` / `EvictRight`), emitting `JoinAggregateEvent<V>` per processed update. 8 tests + 1 doctest. Pairwise binary join is now end-to-end usable.
- [x] **SWAG multi-way join — layer 5a** in `cqels-core::operator::swag_multiway`: `MultiWayAggregateSpec` trait (generalized ring contract for N-way aggregation) + built-in `MultiWayCount` and `MultiWaySumProduct` specs + `MultiWayJoinState<E, K, S>` recursive F-IVM executor over a `JoinGraph`. Per-edge `CTrieIndex` per `(relation, neighbor)` pair; `insert` returns the F-IVM positive delta, `delete` returns the negation, both fold into the running aggregate. 10 tests covering binary / triangle / star / SumProduct / clear / validation. **Diverges from Java's `computeBinaryDelta` shortcut**: Java uses binary delta whenever the inserted relation has degree 1, which yields incorrect partial deltas for multi-way star topologies. The Rust port gates the binary fast path on `graph.relation_names().len() == 2` instead, preserving F-IVM semantics.
- [x] **SWAG triangle spec — layer 5b** in `cqels-core::operator::swag_triangle`: `TriangleJoinAggregateSpec` trait (3-way variant with type-safe per-relation payload types `PA`, `PB`, `PC`) + `TriangleCount<A, B, C>` + `TriangleSumProduct<A, B, C, FA, FB, FC>` built-in specs. Mirrors Java's `TriangleJoinAggregateSpec`. The trait is type-safe convenience surface; native execution falls through to `MultiWayJoinState` via the shared-payload path (triangle topology already runs cleanly there, as proven by Layer 5a's `triangle_multiway_count_matches_three_way_join` test). 10 tests + 1 doctest.
- [x] **SWAG multi-way range cache — layer 5c** in `cqels-core::operator::swag_multiway_cache`: bounded `RangeCache<K, E, P>` keyed by `(relation, driver, join_key, start, end)`, with `get` / `put` / `invalidate_relation` / `clear`. Memoizes per-edge range-query results during `MultiWayJoinState::recursive_join`; eagerly invalidated by relation on every `insert`/`delete` so the cache never shows stale data. FIFO eviction (vs Java's access-ordered LRU) — same hit-rate within a single delta computation, no new dependency. Default capacity 1024 entries, matching Java. 9 cache-unit tests + 3 integration tests on `MultiWayJoinState`.
- [x] **SWAG parallel join aggregator — layer 5e** in `cqels-core::operator::swag_parallel`: `ParallelJoinAggregator<S>` that takes two payload `TimeIndex`es + interval bounds and recomputes the join aggregate from scratch in parallel using rayon's work-stealing scheduler. Sequential fallback below a configurable threshold (default 1000, matching Java). Pairs with new `WindowJoinState::{left_time_index, right_time_index}` accessors (cross-product mode only). 5 tests including incremental-vs-parallel equivalence on workloads above and below the parallel threshold. Java uses Fork/Join + a hand-rolled `ExponentialSplitter`; rayon's scheduler subsumes the splitter so the `growthFactor` knob is absent here.
- [x] **SWAG windowed join operator — layer 5d** in `cqels-core::operator::swag_windowed_join`: `WindowedJoinAggregateOperator<S, K, W>` that owns per-`(join_key, window_id)` `WindowJoinState` partitions. `process_left` / `process_right` route events through a pluggable `WindowAssigner<W>`, returning one `JoinAggregateResult` per assigned window. Lifecycle methods: `fire_window(key, window)` reads the running aggregate, `purge_window(key, window)` drops the partition, `clear()` empties all state. Ships `TumblingWindowAssigner` as a canonical impl; sliding/session/custom assigners plug in via the trait without touching the operator. 9 module tests + 1 doctest. Java's Reactor `Flux`/`Mono` envelope is replaced by synchronous methods returning `Vec<Result>` — callers wrap on their own async story if needed.
- [x] **SWAG multi-way `delete_range` — layer 5f** in `cqels-core::operator::swag_multiway`: `MultiWayJoinState::delete_range(relation, start, end) -> V` enumerates every `(timestamp, element)` occurrence in `[start, end]` via the relation's per-edge `CTrieIndex` (which stores full `JoinRecord<E, P>`), then replays each through the regular `delete` path to recover the F-IVM negative delta. 4 tests covering empty-range / no-match / bag multiplicity / triangle topology end-to-end. **Surpasses Java's implementation**, which itself notes `deleteRange` returns zero delta because Java's `TimeIndex` only stores payloads. The Rust port keeps full elements in `JoinRecord` and so closes that gap.

**3a complete.** All five SWAG-join layers + their five sub-slices (5a–5f) are landed. The full F-IVM pipeline — pairwise and N-way, with topology planner + range cache + parallel recompute + windowed key partitioning — is in `cqels-core::operator`.

### 3b Persistent storage backends

- [x] **`cqels-storage-sled`** — production-grade embedded backend using the pure-Rust `sled` KV store. 8 tests.
- [x] **`cqels-storage-lmdb`** — production-grade embedded backend using the pure-Rust `heed` LMDB binding (memory-mapped, MVCC). 8 tests.
- [x] **`cqels-storage-rocksdb`** — RocksDB backend (mirrors Java's `cqels-storage-rocksdb`). The previously-blocking `links = "rocksdb"` collision between the user-space `rocksdb` crate and oxigraph's transitive `oxrocksdb-sys` was lifted by disabling oxigraph's `rocksdb` *default* feature at the workspace level: we only use `Store::new()` (the in-memory variant available unconditionally), never `Store::open(path)` (the rocksdb-gated API). Column-family layout: `journal`, `checkpoints`, `meta`. Uses `delete_range_cf` for cheap range truncation. 8 tests, same shape as the sled backend.
- [x] **`cqels-storage-iotdb`** — Apache IoTDB-backed adapter (mirrors Java's `cqels-storage-iotdb`). Lifts the "network database, large surface, no concrete driver" deferral by splitting the integration: a narrow async `IotDbExecutor` trait (`put`, `read_from`, `latest`, `delete_range`, `close`) captures exactly what the SPI needs, and a full-functioning `InMemoryIotDbExecutor` (backed by per-device `BTreeMap<u64, Vec<u8>>`) ships as the default backend. Storage maps `offset → IoTDB time`, journal device + checkpoint device + reserved key-0 meta row for next-offset recovery across reopens. 14 unit tests (executor-level + backend-level) all green.
  - **`thrift` feature** (opt-in): `ThriftIotDbExecutor` built on `iotdb-client-rs::RpcSession`. Because the Thrift `Session` carries `dyn TInputProtocol / TOutputProtocol` trait objects without `Send + Sync`, the session is pinned to a dedicated OS worker thread; async methods forward commands over `tokio::sync::mpsc` channels with one-shot reply slots. The executor handle is `Send + Sync` (just an mpsc sender). Payload bytes encode as base64 in a single TEXT measurement per device because the client's `Value` enum has no Binary variant. Live integration test gated by `IOTDB_HOST` env var + `#[ignore]`; plus a compile-time type-plumbing test and a `connect_to_dead_endpoint_yields_clean_error` test that doesn't need a live server.

### 3c External integration modules

- [x] **`cqels-mcp` crate** — protocol-agnostic tool layer + JSON-RPC 2.0 transport over stdio + executable server binary. Tool surface: `parse_query`, `query` (dry-run), `analyze_query` (compiler-decision view including self-join hints), `reasoning_profiles`, `shacl_capabilities`, `reason` (one-shot RETE inference), plus `store_memory`/`recall_memory`/`forget_memory` (in-memory or sled-backed). JSON-RPC methods: `initialize`, `ping`, `tools/list`, `tools/call`. Notifications, parse errors, invalid JSON-RPC versions, and unknown methods all handled correctly. Run with `cargo run -p cqels-mcp --bin cqels_mcp_server` and pipe JSON-RPC on stdin. 43 tests. Follow-up tools that still need engine wiring: live `validate`/`solve`.
- [x] **Engine-bound stream-query tools** (`stream_query` module): `register_stream_query`, `list_stream_queries`, `unregister_stream_query`, `poll_stream_results`. A `StreamQueryHub` holds an `Arc<CqelsEngine>` + tokio `Handle` and routes streamed `BindingSet` results into a per-query FIFO buffer that MCP clients drain via `poll_stream_results`. 8 tests covering registration round-trip, listing, unregister + buffer-clear, parse-error propagation, and FIFO drain semantics.
- [x] **`validate` MCP tool** (`validate` module): bridges `cqels-shacl::ShaclValidationEngine` to the MCP surface. Takes `shapes` + `data` triple arrays, runs SHACL validation through an `AspSolver`, and returns structured violations plus optional repair candidates. Default constructor uses `ClingoSubprocessSolver` (clingo-conditional); a `validate_tool_with_solver` constructor accepts any `Arc<dyn AspSolver>` for testing or custom backends. 8 unit tests use a recording `MockSolver` to verify conforming/violation paths, error propagation, and that data triples thread into the generated ASP program.
- [x] **`solve` MCP tool** (`solve` module): direct ASP-solver bridge. Takes a raw ASP-Core-2 `program` string + `max_models` (0 = enumerate all), returns the answer sets as `{predicate, terms}` atom arrays. Same constructor pattern as `validate`: `solve_tool()` default with `ClingoSubprocessSolver`, `solve_tool_with_solver(Arc<dyn AspSolver>)` for tests. 8 unit tests cover canned answer sets, program + max_models pass-through, default `max_models = 1`, solver-error propagation, missing-program rejection, UNSAT (empty list), and multi-model enumeration.
- [x] **`cqels-cdsp` Rust port:** COVESA Vehicle Signal Specification (VSS) signal-ingestion adapter. Provides `VssSignal` + `VssValue` (Bool/Int/Float/String) envelope, a `VssSignalMapper` that produces an `RdfStreamElement` from a signal using a configurable `PredicateStrategy` (`PrefixedPath` or `Slashed`), and an async `VssSignalSource` trait with a reference `ChannelVssSignalSource` backed by `tokio::sync::mpsc`. 16 default-feature unit tests + 1 doctest.
  - **`kuksa` feature** (opt-in): `KuksaVssSignalSource` built on `kuksa-rust-sdk`'s gRPC Databroker v2 client. Unlike the IoTDB Thrift client, kuksa-rust-sdk is fully async / `Send + Sync` (tonic-based), so no worker-thread workaround is needed — a single background tokio task drains the subscription stream into a bounded `tokio::sync::mpsc` channel that back-pressures producers when consumers fall behind. `connect()` validates the subscription synchronously (bad endpoint or unknown path surfaces immediately rather than from the first `next()`). Value mapping lifts kuksa's scalar `TypedValue` variants to the narrower `VssValue` (`Int32/Int64/Uint32`→`Int(i64)`; `Uint64` lifts only when it fits, otherwise drops; `Float/Double`→`Float(f64)`; arrays drop). 10 new unit tests + a `connect_to_dead_endpoint_yields_clean_error` test that doesn't need a server + a `kuksa_live_subscription_delivers_signals` integration test gated by `KUKSA_HOST`.

## Out of scope (intentional)

- Porting Java's reflection-heavy `BinaryCodecRegistry` generic dispatch — the byte-based Rust SPI is fine for the backends we'll add.
- Re-introducing the separate `cqels-reasoning-rete` crate — folded `cqels-reasoning` is simpler.
- Java's mislabeled `cqels-s2` (which is Lucene semantic search, not S2 cells).
